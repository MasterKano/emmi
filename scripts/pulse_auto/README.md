Local command: `/workspace/brief/auto/pulse_auto.sh` (build/check only), or add `--publish` (checked branch + PR + green checks + merge). Existing weekday Pulse, editorial, sent records and email are not changed. No LLM calls or SMTP. A future short bot step can send only after the fixed status is ready/published and validation is PASS.

## Locked template
Source of truth: `/workspace/brief/master/README.md`, current approved `market_pulse_weekday_master_v1.3.1` (11 November 2026: v1.3 plus email PNGs written 600px wide on disk, with a build-failing PNG-width check). v1.2 and v2 were superseded. ## Safety gate
Fresh fetch on every run. Source dates for displayed board prices, risk gauges/breadth, power delivery, wind/hydro, nuclear MTD, gas storage and TTF curve are recorded in `validation.json` alongside failures/gaps. Core market prices and Nordic power require the latest completed session/delivery data. Jerry approved the explicit one-business-day allowance for named slower sources on 11 Nov 2026 at 07:20 Zurich (card t1089s3453); every lagged value gets an as-of label. See freshness-rule-audit.md. Every required chart must exist. Missing text values, empty tables, wrong chart ordering, phone overflow or a column-width failure (an image without max-width:100%, a fixed width above 600px, or an email PNG wider than 600px on disk) hold publication. The commentary slot is the sole deliberate empty editorial slot. Pilot-only gas feed constants point to emmi-data after the 5 November split; existing builders are untouched.

Output: `/workspace/brief/out/pulse_auto/YYYY-MM-DD/HHMMSS/` contains HTML, PNGs, source provenance, phone results and checklist. Nothing touches `out/pulse`, editorial files or reported sent stories. `CHECK_PASS` hashes the validation report; the publisher rechecks report and HTML/image hashes, date, and build age (under 2h). Only HTML and referenced PNGs go public. Validation/provenance files remain local. A date already archived is immutable: reruns retain it. Publication does not imply email was sent.

URLs: `/emmi/pulse/` is the site’s Latest Pulse page (EMMI chrome around the newest *emailed* edition); `/emmi/pulse/YYYY-MM-DD/` is the emailed weekday or Weekend Pulse (page around `email.html`, the sent HTML); this pilot goes to `/emmi/pulse/YYYY-MM-DD-pilot/` (`email.html` is the vetted pilot HTML, unchanged) and never replaces an emailed edition or `latest.json`; `/emmi/pulse/archive/` is the site archive list. After a successful send, `scripts/editions/publish_sent.py` puts the sent HTML and its images on the site (no email, no date gate). The site remains public, with noindex; no password gate is added to Pulse. `scripts/site_files.sh` includes only this dedicated static output folder. Publication does not imply email was sent.

## Routine execution (box timer dropped)
A Grok Bot routine can invoke `/workspace/brief/auto/pulse_auto.sh --publish` weekdays around 05:30 Europe/Zurich. This change does not create/edit any routine or email. All pilot box timer/service/cron configuration was removed; the old intraday trigger is untouched.

The command has a kernel flock and a 300-second deadline (+10-second forced-stop grace). Fixed atomic status: `/workspace/brief/out/pulse_auto/latest_status.json`. Final states: `published` (dated URL serves the exact vetted edition HTML, and the latest and archive URLs are the site pages for that date), `ready` (clean dry run, nothing published), or `held` (reason list, no permission to send). `building` is transient. Exit codes: 0 ready/published, 2 validation held, 1 build/publish error, 75 overlap, 124 deadline (137 if forced kill). Status includes reasons, output_dir where applicable, page_url and Zurich timestamp. Dry-run command omits `--publish`.

Idempotence: if today's archive is already on main, verify both real URLs and return already_published without rebuilding or opening a PR. Otherwise use one deterministic `pulse-auto/YYYY-MM-DD` branch/PR. An atomic local journal under `out/pulse_auto/transactions/` preserves the checked output/head SHA before push; retries validate and resume that same transaction rather than opening duplicates. Unknown/changed/expired remote transactions hold for review. No force-push or archive replacement.
